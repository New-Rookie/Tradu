# 旅渡 TravelDu V1 前端页面与交互流程

## 1. 页面结构

```text
首页
  ├─ 开始规划 → 需求填写页
  └─ 导入攻略 → 攻略导入页

需求填写页
  └─ 调用 /api/v1/itineraries/generate → 方案结果页

攻略导入页
  ├─ 调用 /api/v1/content/extract
  └─ 确认地点后进入方案生成

方案结果页
  ├─ 展示 plans / days / items
  └─ 查看地图 → 地图展示页

地图展示页
  ├─ 调用 /api/v1/pois
  └─ 显示 Marker 与路线占位
```

## 2. V1 前端设计原则

1. 先保证完整闭环，不追求复杂视觉效果。
2. 页面布局采用左侧信息、右侧地图或结果卡片的结构。
3. 所有后端请求都通过 `src/api` 统一封装。
4. 行程数据统一保存到 Pinia Store，避免页面之间反复传参。
5. 地图组件先显示点位 Marker，Polyline 路线后续等正式路线服务完成后再接入。

## 3. 页面验收

| 页面 | 核心验收 |
|---|---|
| 首页 | 能跳转到规划和攻略导入 |
| 需求填写页 | 能提交表单并拿到后端方案 |
| 攻略导入页 | 能抽取 POI |
| 方案结果页 | 能展示五套或临时方案 |
| 地图展示页 | 能显示重庆 POI Marker |
