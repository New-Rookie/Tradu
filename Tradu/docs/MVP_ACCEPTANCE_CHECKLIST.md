# 旅渡 V1 MVP 验收清单

## 1. 后端可用性

- [ ] `GET /health` 返回 `status=ok`
- [ ] `GET /api/v1/pois` 返回 30 条重庆 POI
- [ ] `POST /api/v1/itineraries/generate` 返回 5 套方案
- [ ] 每套方案包含 3 天路线
- [ ] 每天路线包含 3 到 5 个点位
- [ ] 每个点位包含 `poi_name`、`longitude`、`latitude`、`poi_type`、`nearby_area`
- [ ] `GET /api/v1/weather?city=重庆` 可返回天气
- [ ] `POST /api/v1/content/extract` 可从攻略文本中提取地点

## 2. 前端可用性

- [ ] 首页能正常打开
- [ ] 规划页能提交重庆 3 天、预算 2500、偏好美食/拍照/夜景
- [ ] 结果页能展示 5 套方案
- [ ] 结果页能展示每日时间轴
- [ ] 结果页能展示预算、步行距离、交通时间
- [ ] 地图页能加载高德地图
- [ ] 地图页能显示 Marker
- [ ] 地图页能显示 Polyline
- [ ] 地图页能切换方案
- [ ] 地图页能切换 Day 1 / Day 2 / Day 3
- [ ] 攻略导入页能提取攻略中的 POI

## 3. 当前可接受的 MVP 简化

- [ ] `poi_id` 允许暂时为空，但必须有 `poi_name + 经纬度`
- [ ] Polyline 允许先用点到点直线，不要求道路级路径
- [ ] 预算允许使用估算区间，不接实时价格
- [ ] 住宿只推荐区域，不接酒店预订
- [ ] 小红书内容只支持用户粘贴文本，不做自动爬虫
- [ ] DeepSeek 先用于结构化抽取，不要求所有行程解释都由大模型生成

## 4. 演示脚本

用户输入：

```text
重庆，3天，预算2500，喜欢美食、拍照、夜景，不想太累
```

系统应展示：

1. 综合最优方案
2. 低预算方案
3. 少走路轻松方案
4. 美食体验方案
5. 经典打卡方案

地图页应展示：

1. 当前方案 Day 1 的 Marker
2. 当前方案 Day 1 的 Polyline
3. 切换 Day 后地图刷新
4. 切换方案后地图刷新
